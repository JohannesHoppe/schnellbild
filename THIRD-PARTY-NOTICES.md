**VLCKit** is built by us from VideoLAN's source, without VLC's modules under the GPL, so every VLC module in it is under the GNU LGPL 2.1 or later: VLCKit 3.7.5 (tag `3.7.5`, commit `a213fd11`) with libVLC 3.0.24 (commit `6de05adc`), built with VideoLAN's own build script for Apple silicon, with these changes: more modules go on VideoLAN's list of modules it leaves out, and five small changes to VLC (`Scripts/vlc-patches/`): four to its subtitle timing (subtitles reach the first pictures of a video) and one to its CoreAudio output (a video seeked into its last second ends).

- VLC's eight modules under the GPL: the Dolby Surround decoder, mono downmix, the dummy interface, syslog logging, the RTSP video-on-demand server, stream output cycle and RTP, the rotate filter.
- The modules a viewer of local files never needs, which a file someone else made could otherwise reach: every network access (HTTP, HTTPS, FTP, SFTP, SMB, NFS, RTSP, UDP, TCP, RIST, SAT>IP, MMS, RTP, SDP, SRT, FFmpeg's network protocols), concat and VDR (they open other files), every access output, the standard stream output and Chromecast, service discovery (Bonjour, UPnP, mDNS), playlists and adaptive streaming (HLS, DASH, Smooth), the directory and NSC readers, the stream filters decomp (it starts `zcat`, `bzcat`, `xzcat` on compressed content), HDS and record, VLC's own archive reader, the keystores, TLS, the folder art finder, Lua, the Flaschen-Taschen video output, the audio file output and the demux dumper.

Schnellbild uses none of them. How it is built, with the exact list: `Scripts/build_vlckit_lgpl.sh`; `Scripts/vlckit_licenses.py --no-gpl --local-only` checks the result. The build is published as a pre-release of this repository, and `Scripts/fetch_vlckit.sh` checks its SHA-256 and the unpacked framework's tree SHA-256. It is embedded as its own framework in `Contents/Frameworks` and linked dynamically. The same VLCKit is in the DMG and in the Mac App Store version.

- **Third-party libraries inside VLCKit:** VLC's build compiles third-party libraries into VLCKit (statically, configured with `--disable-gpl`), each under its own license (LGPL, BSD, MIT, zlib-style and similar). Among them, as their names and versions show in the current build: FFmpeg (libavcodec, libavformat, libavutil, libswscale; GNU LGPL 2.1 or later, built without its GPL parts), dav1d, libvpx, aom, libass, FreeType, HarfBuzz, FriBidi, libxml2, libpng, bzip2, Ogg, Vorbis, Theora, FLAC, Opus, Speex, mpg123, TagLib, soxr, libebur128, libdvbpsi, zvbi, libplacebo, libmodplug, spatialaudio, libarchive, libgcrypt, libssh2, libsmb2, libnfs, libdsm, live555 and libupnp. The build collects the license files of every library it compiled into `VLCKit-third-party-licenses.txt`, published with each VLCKit pre-release; the app ships it in `Contents/Resources/Licenses` ([Resources/Licenses/VLCKit-third-party-licenses.txt](Resources/Licenses/VLCKit-third-party-licenses.txt)).
- **Source code:** VLCKit 3.7.5 at <https://code.videolan.org/videolan/VLCKit> (tag `3.7.5`), VLC at <https://code.videolan.org/videolan/vlc> (commit `6de05adc`), and our build script in this repository. Each VLCKit pre-release of this repository also carries the complete source it was built from: VLCKit at the tag with the change to its build script, VLC with VLCKit's patches applied, our changes to VLC (`VLC-schnellbild-changes.patch`, applied on top), and the downloads of every third-party library (`VLCKit-contrib-sources.tar`). On request we send a copy of exactly this source, for no more than the cost of sending it; write to us via the issues of this repository. This offer is valid for three years from each release of the app.
- **Replacing VLCKit:** the app's complete source is in this repository. Put the modified `VLCKit.xcframework` into `Vendor/` and run `SCHNELLBILD_OWN_VLCKIT=1 Scripts/build_app.sh`: with that variable the build uses the framework found there as it is, so the app can be rebuilt and run with a modified VLCKit. The Mac App Store version's license agreement allows changing VLCKit for your own use and reverse engineering to debug such changes, as the LGPL asks.

**UnRAR** is compiled from the official source (`Scripts/fetch_unrar.sh` checks its SHA-256) with one change: its error state (`ErrHandler` in `global.hpp`) is kept per thread (`thread_local`), so archives read at the same time don't see each other's errors; `Native/CArchives/rar_shim.cpp` is Schnellbild's own code around it. From its license: *UnRAR source code may be used in any software to handle RAR archives without limitations free of charge, but cannot be used to develop RAR (WinRAR) compatible archiver and to re-create RAR compression algorithm, which is proprietary.*

**The map data** comes from OpenStreetMap through Protomaps' daily build (the date is in `Scripts/map_data.env`); `Scripts/build_map_data.py` keeps zoom 0 to 7 of the layers earth, water, boundaries, roads and the glaciers of landuse, and the countries, regions and localities of the places layer, with names in the app's 20 languages. Each place's country code comes from [Natural Earth](https://www.naturalearthdata.com) (public domain). The files (named after Schnellbild, as Protomaps asks of changed builds) are a derivative database under the ODbL, published with their notice as assets of a pre-release of this repository (`map-<date>`), where anyone can download them; `Scripts/fetch_map.sh` checks their SHA-256 for every build. The map in the app shows "© OpenStreetMap" in its corner (an ⓘ after a few seconds), with the link to <https://www.openstreetmap.org/copyright>.
